Nimble

Lenguaje de scripting interpretado, sencillo y embebible. Guía completa v0.11.

Novedades de v0.10 / v0.11 nuevo

Resumen de lo que cambió después de v0.9 (más abajo queda el detalle histórico de la auditoría de v0.9). Si vienes de v0.9, esto es lo nuevo:

Módulo net: sockets TCP/UDP v0.10

Nuevo módulo net con sockets TCP y UDP crudos, bloqueantes y sin dependencias externas (BSD sockets en Linux/macOS, Winsock2 en Windows). Pensado para mini-servidores de prueba, protocolos de juego simples o probar un cliente a mano. Ver la sección completa net más abajo. 

use net

srv = net.tcp_listen("127.0.0.1", 9000)
conn = srv.accept()
print(conn.recv())
conn.send("ok\r\n")
Bug corregido durante esta actualización: igual que le pasó a gc en v0.9 (ver más abajo), net se registró como módulo nativo pero se olvidó agregarlo a la lista interna que usa la sentencia use para reconocer módulos nativos. El síntoma era idéntico: use net fallaba con Could not import module 'net.nimble' (not found: net.nimble), como si use intentara cargarlo como archivo del proyecto. Ya está corregido — use net, use net as n y use net (tcp_connect, resolve) funcionan los tres.

Escape \r en strings v0.11

Antes, el único juego de escapes reconocido dentro de un string entre comillas era \n, \t, \", \\, \{ y \}. \r no estaba en esa lista, así que caía al caso por defecto y quedaba tal cual — dos caracteres literales, la barra invertida y la r — en vez de convertirse en un retorno de carro real (0x0D). Esto pasaba desapercibido en la mayoría del código, pero se volvió un problema real con la llegada de net: muchos protocolos de texto sobre sockets (HTTP a mano, SMTP, IRC, líneas terminadas en CRLF) necesitan "\r\n" exacto para separar líneas. 

# Antes de v0.11:
s = "linea1\r\nlinea2"
length(s)     # 16 -- \r quedaba como los DOS caracteres '\' y 'r', no como 0x0D

# Desde v0.11, \r es un escape real:
s = "linea1\r\nlinea2"
length(s)     # 15 -- \r es un solo byte (0x0D), como \n

# Útil para protocolos de línea sobre net.*:
use net
c = net.tcp_connect("example.com", 80)
c.send("GET / HTTP/1.1\r\nHost: example.com\r\nConnection: close\r\n\r\n")
Si dependías del comportamiento viejo: algún código que escribía "\r" esperando literalmente la barra invertida y la letra r (en vez de un retorno de carro) ahora obtiene un byte distinto y probablemente una string un carácter más corta. Es poco probable que algo dependiera de ese bug a propósito, pero si tenías tests que comparaban longitudes exactas de strings con \r sin escapar como raw string (r"..."), revísalos.

Otras adiciones de biblioteca estándar v0.10

  • string.starts_with(prefijo) / string.ends_with(sufijo) — lo único que faltaba en los chequeos de string; contains() y find() no sirven para esto porque no anclan a una posición.
  • list.index_of(valor) — posición de un valor dentro de una lista (o -1 si no está), sin escribir el bucle a mano. Usa la misma igualdad estructural que ya usan == y in.
  • math.round(x, decimales) — redondeo a N decimales, como función nueva en math en vez de un segundo argumento en el round() global (que sigue funcionando igual que siempre, de un solo argumento).
  • path.basename() / path.dirname() — reescritos sobre std::filesystem::path. Antes buscaban '/' a mano, así que una ruta estilo Windows (C:\Users\foo\bar.txt) en Linux/macOS devolvía la ruta completa como si fuera el "basename". Ahora entienden ambos separadores.
use math

"nimble.txt".starts_with("nim")   # true
"nimble.txt".ends_with(".txt")   # true

[10, 20, 30].index_of(20)   # 1
[10, 20, 30].index_of(99)   # -1

math.round(3.14159, 2)   # 3.14
round(3.14159)          # 3  (global round(), sin cambios: siempre 0 decimales)

Novedades de v0.9 correcciones

La v0.9 nació de una auditoría de la propia documentación: se probó cada ejemplo documentado contra el intérprete real, y eso encontró varios bugs — tres de comportamiento/API, y dos más graves de estabilidad que salieron a la luz al revisar el código fuente en detalle. Si vienes de v0.8, esto es lo que cambia para ti:

1. json.decode() ya no puede tirar el proceso crash corregido

Antes, un json.decode(...) con entrada malformada — incluyendo casos tan simples como "{}" en ciertas rutas — podía terminar en un std::terminate sin que try/catch pudiera hacer nada, porque el error escapaba como una excepción de C++ no relacionada con Nimble (std::invalid_argument) en vez de un NimbleError capturable.

La causa raíz estaba en la interpolación de strings: cuando el contenido entre { } no lograba parsear como expresión, en vez de fallar se sustituía silenciosamente un texto de relleno, y ese texto era lo que después llegaba sin protección al parser de números de json.decode. Ahora ambas cosas están arregladas:

  • Una interpolación inválida lanza un NimbleError capturable, en vez de producir un resultado silenciosamente incorrecto.
  • json.decode() valida números, true, false y null antes de consumirlos, así que ninguna entrada puede tirar el proceso — como mucho lanza un NimbleError normal.
  • json.decode() también exige que las claves de un objeto sean strings (como manda el propio estándar JSON): una entrada como {1: 2} antes llegaba a intentar leer la clave como string y crasheaba igual que el caso de números malformados; ahora se rechaza con un NimbleError claro.
# Antes de v0.9 esto podía crashear el proceso entero.
# Ahora simplemente lanza un error capturable:
use json

try
    obj = json.decode("{esto no es json válido}")
catch err
    print("JSON inválido: {err}")
end

# También afecta a la interpolación: una expresión rota entre { }
# ahora es un error, no un texto de relleno silencioso.
try
    x = "resultado: {1 +}"   # expresión inválida dentro de { }
catch err
    print("Interpolación inválida: {err}")
end

2. Value(42) y Value("texto") ya hacen lo que parecen hacer API de embebido

Esto solo afecta a código C++ que embebe Nimble (ver Trabajar con Value), pero era una trampa seria: antes de v0.9, Value(42) ni siquiera compilaba (ambigüedad entre Value(double) y Value(bool)), y Value("texto") compilaba sin error pero producía un booleano true — porque la conversión de puntero a bool gana la resolución de sobrecarga frente a la conversión (definida por el usuario) de const char* a std::string. Cualquier ejemplo de la documentación que escribiera un literal directamente estaba afectado. 

// Antes de v0.9:
Value(42)        // ERROR de compilación (ambiguo)
Value("hola")     // compila, pero es Value(true) -- ¡un booleano!, no el string "hola"

// A partir de v0.9, ambos hacen lo esperado:
Value n(42);          // number: 42
Value s("hola");       // string: "hola"
Si tienes código de embebido de antes de v0.9: revisa cualquier Value("literal") que hayas escrito directamente con una cadena entre comillas. Antes tenías que envolverlo como Value(std::string("literal")) para que funcionara; ahora ambas formas dan el mismo resultado correcto, pero si tu código dependía (a propósito o sin darse cuenta) del valor true que producía el bug, ese comportamiento ya no ocurre.

3. for i, x in enumerate(lista) ya funciona bug de comportamiento

El for con dos variables ya funcionaba correctamente sobre mapas (for clave, valor in mapa), pero sobre una lista de pares —como la que produce enumerate()— antes solo asignaba el par completo a la primera variable y dejaba la segunda sin definir. Esto rompía silenciosamente el idioma más común para usar dos variables de bucle. Ahora, sobre una lista, el for con dos variables destructura cada elemento (asumiendo que es una lista de 2 elementos) en las dos variables, igual que ya hacía con mapas. 

nombres = ["ana", "luis", "eva"]

# Antes de v0.9: `i` recibía [0, "ana"] completo y `x` quedaba indefinida.
# Desde v0.9: `i` recibe 0 y `x` recibe "ana", como cabría esperar.
for i, x in enumerate(nombres)
    print("{i}: {x}")
end
# 0: ana
# 1: luis
# 2: eva

# También funciona con cualquier lista de pares hecha a mano:
for clave, valor in [["a", 1], ["b", 2]]
    print("{clave} = {valor}")
end
Si un elemento de la lista no tiene exactamente 2 elementos, se lanza un NimbleError explicando que cada ítem debe ser una lista de 2 elementos (como la que produce enumerate()), en vez de fallar en silencio.

Introducción

Nimble es un intérprete de scripting escrito en C++17. Su sintaxis es limpia, con bloques terminados en end (al estilo Ruby/Lua), tipado dinámico y una biblioteca estándar práctica. Está diseñado para dos usos:

  • Como CLI: ejecutar scripts .nimble desde la terminal o en un REPL interactivo.
  • Embebido en C++: incrustarlo en un juego, herramienta o aplicación para permitir scripting por parte del usuario, con control total de permisos y límites.
Filosofía: bloques claros, cero magia, y una API de embebido pequeña y explícita.

Compilar y ejecutar

Nimble es un único archivo nimble.cpp. No requiere dependencias externas salvo libcurl si quieres usar http.

Compilación básica (CLI)

# Linux / macOS
g++ -std=c++17 -O2 nimble.cpp -o nimble

# Con soporte HTTP
g++ -std=c++17 -O2 -DHAVE_CURL nimble.cpp -o nimble -lcurl

# Windows (MinGW)
g++ -std=c++17 -O2 nimble.cpp -o nimble.exe

Ejecutar un script

./nimble mi_script.nimble
./nimble run mi_script.nimble arg1 arg2
./nimble test mi_script.nimble          # ejecuta los tests definidos
./nimble --no-warn mi_script.nimble     # desactiva advertencias

Los argumentos posteriores al nombre del archivo quedan disponibles en el script como system.args (una lista).

REPL interactivo

Si ejecutas nimble sin argumentos, entra en modo interactivo:

$ ./nimble
Nimble REPL (v0.9) -- type 'exit' to quit
> 2 + 2
4
> func saludar(nombre) return "Hola, " + nombre end
> saludar("mundo")
Hola, mundo
> exit

Puedes escribir bloques multilínea; el prompt cambia a ... hasta cerrarlos. También puedes salir con exit() o salir.

Interpolación

Dentro de un string normal, {expr} evalúa y muestra el valor:

for

La forma con una variable funciona sobre listas, strings (carácter a carácter) y mapas (recorriendo las claves): 

for x in [1, 2, 3]
    print(x)
end

# Iterar sobre strings, carácter a carácter
for c in "abc"
    print(c)
end

# Iterar sobre mapa: una var = solo las claves
edades = {ana: 30, luis: 25}
for nombre in edades
    print(nombre)     # "ana", luego "luis"
end

La forma con dos variables (for a, b in ...) sirve para dos casos distintos, según el tipo de lo que iteres:

  • Sobre un mapa: a recibe la clave y b el valor.
  • Sobre una lista: cada elemento debe ser en sí mismo una lista de 2 elementos (un "par"), y ese par se destructura en a y b. Esto es justo lo que hace falta para el idioma for i, x in enumerate(lista), el uso más común de la forma de dos variables.
# Dos variables sobre un mapa: clave + valor
for nombre, edad in edades
    print("{nombre} tiene {edad}")
end

# Dos variables sobre una lista de pares (lo que produce enumerate()):
# índice + valor, el idioma más habitual para numerar elementos
frutas = ["manzana", "pera", "uva"]
for i, fruta in enumerate(frutas)
    print("{i}: {fruta}")
end
# 0: manzana
# 1: pera
# 2: uva

# También funciona con cualquier lista de pares construida a mano,
# por ejemplo el resultado de zip():
nombres = ["ana", "luis"]
puntos  = [10, 20]
for nombre, punt in zip(nombres, puntos)
    print("{nombre}: {punt} pts")
end
Corregido en v0.9 fix: antes, la forma de dos variables sobre una lista solo asignaba el par completo a la primera variable y dejaba la segunda sin definir. Si ya usabas for i, x in enumerate(...) antes de v0.9, revisa esos bucles: ahora x recibe el valor real, no null/indefinido.
Si un elemento de la lista no es exactamente una lista de 2 elementos, se lanza NimbleError en vez de fallar en silencio.

4. use gc ya funciona módulo inaccesible por use

El módulo gc (ver gestión de memoria / gc) siempre estuvo registrado como módulo nativo igual que math, json, etc., pero la lista interna que la sentencia use usa para reconocer los módulos nativos se había quedado corta y no lo incluía. El resultado: escribir exactamente el ejemplo que la propia documentación mostraba tiraba un error. 

# Antes de v0.9, esto fallaba con:
# "Could not import module 'gc.nimble' (not found: gc.nimble)"
# porque 'use' intentaba cargarlo como un archivo del proyecto.
use gc
gc.collect()
print(gc.stats())
Dato curioso mientras se investigaba esto: los módulos nativos (math, json, gc, etc.) en realidad son visibles como variables globales sin necesidad de use — use para un módulo nativo solo importa cuando quieres un alias (use gc as g) o una importación selectiva (use gc (collect, stats)). Por eso el impacto real de este bug era limitado (gc.collect() sin la línea use gc ya funcionaba), pero cualquiera de las tres formas de use gc — a secas, con alias o con lista de nombres — seguía estando rota hasta esta versión.

5. Los argumentos con el tipo equivocado ya no crashean el proceso seguridad del sandbox

Este es el hallazgo más serio de la auditoría. Decenas de funciones nativas — ord, read/write/append, los métodos de string (replace, find, contains, split, join), min/max, map/filter/ reduce/zip/enumerate/sum/any/ all, y prácticamente todo time, system, regex, hex, env, csv y http — tomaban un argumento del script y accedían a él directamente (a[0].asStr(), a[0].asList(), a veces incluso a[0] sin comprobar que hubiera suficientes argumentos) sin verificar antes que fuera del tipo esperado.

Cuando el tipo no coincidía, eso disparaba una excepción de C++ pura (std::bad_variant_access o std::out_of_range) que no es un NimbleError. Ningún try/catch del script podía detenerla, y el proceso entero terminaba abortado (SIGABRT). Para un host que usa el sistema de permisos para ejecutar scripts no confiables, esto anulaba por completo la protección: bastaba un argumento del tipo equivocado — por accidente o a propósito — para tirar el proceso, sin que allowFileWrite: false, allowNetwork: false ni ningún otro permiso pudiera evitarlo. 

# Los tres ejemplos siguientes crasheaban el PROCESO ENTERO antes de v0.9
# (no solo lanzaban un error de Nimble):
"abc".replace(5, "x")    # replace() esperaba un string, no un número
ord(42)                 # ord() esperaba un string
min([])                    # min() de una lista vacía

# Ahora, los tres simplemente lanzan un NimbleError normal y capturable:
try
    "abc".replace(5, "x")
catch err
    print("error: {err}")   # replace(): argument 1 must be a string, got number
end
Si embebes Nimble para correr scripts no confiables, esto es la corrección de seguridad más importante de v0.9: antes, ningún conjunto de permisos del SandboxPermissions podía impedir que un script (accidental o malicioso) tumbara el proceso host completo con un solo argumento del tipo equivocado.

Clases

class Animal
    func init(nombre)
        self.nombre = nombre
    end

    func hablar()
        return "...?"
    end

    func describir()
        return "{self.nombre} dice {self.hablar()}"
    end
end

class Perro extends Animal
    func hablar()
        return "Guau"
    end
end

d = Perro("Rex")

El constructor es siempre el método init. Se invoca automáticamente al llamar Clase(args).

Herencia: simple (un solo padre). Los métodos se buscan recursivamente en la cadena de clases base. La búsqueda de métodos está cacheada para mejor rendimiento v0.7.

Errores y excepciones

throw / try / catch / finally v0.8

func dividir(a, b)
    if b == 0
        throw "No se puede dividir entre cero"
    end
    return a / b
end

try
    print(dividir(10, 0))
catch err
    print("Error: {err}")
finally
    print("Esto siempre se ejecuta")
end

catch captura tanto throw del script como errores internos del intérprete (variables no definidas, tipos, etc.). El valor capturado es el valor tirado o el mensaje del error.

finally se ejecuta siempre: tanto si el bloque try termina bien, como si lanza un error, como si se captura, como si hay un return/break/continue en vuelo. Su propio flujo de control tiene precedencia (igual que en Java/Python/JS).

assert y panic

assert(x > 0)                    # aborta si es falso
assert(x > 0, "x debe ser positivo")

panic("estado imposible")          # aborta siempre
Importante: assert y panic lanzan una señal no capturable (AbortSignal). Un try/catch del script no puede detenerlos. Igual sucede con los límites de ejecución.

exit(code) v0.8

if error_critico
    print("Saliendo...")
    exit(1)   # termina el proceso con código 1
end

exit() lanza una ExitSignal que solo se captura en el nivel más externo (main/REPL/test runner), permitiendo que todos los destructores RAII se ejecuten correctamente antes de terminar.

Entrada malformada

Trata siempre la entrada de json.decode() como no confiable (viene de un archivo, una respuesta HTTP, etc.) y envuélvela en try/catch: 

try
    obj = json.decode(texto_no_confiable)
catch err
    print("JSON inválido: {err}")
    obj = {}
end
Corregido en v0.9 fix: antes, json.decode() con entrada malformada podía terminar el proceso entero (std::terminate) sin que ningún try/catch del script pudiera evitarlo, porque el parser de números no validaba el texto antes de convertirlo. Ahora valida números, true, false y null antes de consumirlos, así que cualquier entrada inválida — incluida la cadena vacía, un objeto vacío mal formado, o basura arbitraria — produce como mucho un NimbleError capturable, nunca un crash.

net v0.10

Sockets TCP y UDP crudos y bloqueantes: sin loop de eventos, sin async, cada llamada de send/recv/accept se queda esperando hasta terminar (o hasta que salte un set_timeout). Pensado para mini-servidores de prueba, protocolos simples de juego, o hablar con algo por socket a mano. No depende de libcurl ni de ninguna librería externa — en Linux/macOS usa sockets BSD estándar, en Windows usa Winsock2 (hay que enlazar con ws2_32 a mano si compilás con MinGW/g++; con MSVC alcanza con el #pragma comment(lib, ...) que ya trae el intérprete).

Gateado por el mismo permiso que http.get/http.post: interp.permissions.allowNetwork. Con allowNetwork = false, cualquier función de net lanza un NimbleError en vez de abrir un socket.
Solo IPv4 por ahora (AF_INET). No hay soporte de IPv6 ni de TLS/SSL — para HTTPS seguí usando http.get/http.post (que sí usan libcurl por debajo).

Funciones del módulo

FunciónDescripción
net.tcp_listen([host], [puerto]) Crea un socket TCP en escucha y devuelve un server. host por defecto "0.0.0.0" (todas las interfaces); puerto por defecto 0 (el sistema operativo elige uno libre — mirá server.port para saber cuál).
net.tcp_connect(host, puerto) Conecta por TCP y devuelve una conn ya conectada. host puede ser un nombre de dominio (se resuelve con getaddrinfo) o una IP.
net.udp_socket([host], [puerto]) Crea y bindea un socket UDP; devuelve un objeto udp. Mismos valores por defecto que tcp_listen.
net.resolve(host) Resuelve un nombre a una IPv4 (string), o lanza error si no se pudo resolver.

server — lo que devuelve net.tcp_listen()

MiembroDescripción
server.portPuerto real en el que quedó escuchando (útil cuando pediste el puerto 0).
server.accept()Bloquea hasta que llega una conexión entrante; devuelve una conn.
server.set_timeout(segundos)Si nadie se conecta dentro del tiempo dado, accept() lanza NimbleError en vez de bloquear para siempre.
server.close()Cierra el socket de escucha.

conn — lo que devuelven net.tcp_connect() y server.accept()

MiembroDescripción
conn.remote_host, conn.remote_portIP y puerto del otro extremo.
conn.send(datos)Envía el string completo (reintenta internamente hasta mandarlo todo); devuelve la cantidad de bytes enviados.
conn.recv([max])Lee hasta max bytes (por defecto 4096) y los devuelve como string. Un string vacío ("") significa que el otro lado cerró la conexión, no que no llegó nada.
conn.set_timeout(segundos)Tiempo máximo para send/recv antes de lanzar error.
conn.close()Cierra la conexión.

udp — lo que devuelve net.udp_socket()

MiembroDescripción
udp.portPuerto real bindeado.
udp.send_to(host, puerto, datos)Manda un datagrama a un destino puntual. Devuelve bytes enviados.
udp.recv_from([max])Bloquea hasta recibir un datagrama; devuelve un mapa {data, host, port} con el contenido y de dónde vino.
udp.set_timeout(segundos)Igual que en TCP.
udp.close()Cierra el socket.
No hace falta .close() explícito: cada handle (conn, server o udp) mantiene internamente su file descriptor con RAII. En cuanto el script deja de tener cualquier referencia a ese handle, el socket se cierra solo. Llamar a .close() a mano sigue siendo buena práctica quirúrgica (cerrarlo apenas termines de usarlo, en vez de esperar a que el recolector de basura lo note).

Ejemplo: servidor y cliente TCP tipo eco

# servidor.nimble
use net

srv = net.tcp_listen("127.0.0.1", 9000)
print("escuchando en el puerto {srv.port}")

while true
    conn = srv.accept()
    print("conexión de {conn.remote_host}:{conn.remote_port}")
    data = conn.recv()
    conn.send("eco: {data}")
    conn.close()
end
# cliente.nimble
use net

c = net.tcp_connect("127.0.0.1", 9000)
c.send("hola\r\n")
print(c.recv())    # "eco: hola\r\n"
c.close()

Ejemplo: hablar HTTP a mano (línea por línea, con \r\n)

Un caso típico donde importa el escape \r nuevo de v0.11: armar a mano el request de un protocolo de texto como HTTP, que exige terminadores de línea CRLF exactos. 

use net

c = net.tcp_connect("example.com", 80)
c.set_timeout(5)
c.send("GET / HTTP/1.1\r\nHost: example.com\r\nConnection: close\r\n\r\n")

respuesta = ""
while true
    chunk = c.recv()
    if chunk == "" break end   # "" == el otro lado cerró
    respuesta += chunk
end
print(respuesta)
c.close()
Para HTTPS o para no lidiar con el protocolo a mano, seguí usando http.get / http.post, que hablan HTTP(S) completo por vos vía libcurl. net es la capa de más bajo nivel, para cuando necesitás el socket crudo (protocolos propios, UDP, servidores).

gc — Recolector de ciclos v0.7

Nimble usa shared_ptr para la gestión de memoria, lo que libera automáticamente todo lo que no forme parte de un ciclo de referencias. Para los ciclos (closures que se referencian a sí mismas, objetos que se apuntan mutuamente, etc.), hay un recolector de ciclos por prueba de eliminación (similar al de CPython).

use gc

gc.collect()   # fuerza una recolección; devuelve cuántos nodos liberó
gc.stats()     # devuelve un mapa con estadísticas

gc.stats() devuelve:

CampoDescripción
trackedNúmero de nodos actualmente rastreados.
last_collectedNodos liberados en la última recolección.
total_collectedTotal de nodos liberados desde el inicio.
El recolector se ejecuta automáticamente cada ~5000 asignaciones de tipos rastreados (Env, FunctionObj, ClassObj). Para la mayoría de scripts no necesitas llamarlo manualmente.

Embebido en C++

El intérprete puede usarse como biblioteca dentro de una aplicación C++. Esta sección documenta la API pública de embebido.

Requisitos

  • Compilador C++17 o superior.
  • Definir NIMBLE_NO_MAIN antes de incluir nimble.cpp.
  • Si tu build system prefiere no incluir un .cpp, compila nimble.cpp con -DNIMBLE_NO_MAIN como unidad de compilación separada y declara la clase en un header propio. Para uso rápido, incluir el .cpp es lo más simple.

Uso básico

// host.cpp
#define NIMBLE_NO_MAIN
#include "nimble.cpp"

#include <iostream>

int main() {
    // Argumentos visibles para el script como system.args
    Interpreter interp({"mi_app", "--modo", "debug"});

    // Código fuente Nimble
    std::string src = R"(
print("Hola desde el script")
for i in range(3)
    print("iteración {i}")
end
)";

    // Lex + parse
    Lexer lex(src);
    auto toks = lex.tokenize();
    Parser parser(toks);
    auto program = parser.parseProgram();

    // Ejecutar
    interp.run(program);
    return 0;
}

Compilar el host

g++ -std=c++17 -O2 host.cpp -o mi_app
# Con curl
g++ -std=c++17 -O2 -DHAVE_CURL host.cpp -o mi_app -lcurl

Registrar funciones nativas

Expón funciones C++ al script con registerNative:

#define NIMBLE_NO_MAIN
#include "nimble.cpp"

int main() {
    Interpreter interp;

    // Firma: Value(std::vector<Value>& args,
    //              std::vector<std::pair<std::string,Value>>& named,
    //              Interpreter& interp)
    interp.registerNative("saludar",
        [](std::vector<Value>& args,
           std::vector<std::pair<std::string,Value>>&,
           Interpreter&) -> Value {
            std::string nombre = args.empty() ? "mundo" : args[0].asStr();
            return Value("Hola, " + nombre + "!");
        });

    interp.registerNative("duplicar",
        [](std::vector<Value>& args, auto&, Interpreter&) -> Value {
            return Value(args[0].asNum() * 2);
        });

    // ...cargar y ejecutar script que use saludar(...) y duplicar(...)
}
Nota: al llamar una función nativa, los argumentos pasados por el script ya están evaluados. Los parámetros nombrados llegan en el segundo vector. No es necesario validar cantidad, pero es buena práctica hacerlo y lanzar NimbleError con un mensaje claro si falta algo.

Llamar funciones del script desde C++

Usa callGlobal para invocar funciones globales definidas por el script (por ejemplo hooks como _ready, _process, on_event):

Interpreter interp;
// ... cargar y ejecutar el script ...

// Llamar sin argumentos
interp.callGlobal("_ready");

// Pasar argumentos
std::vector<Value> args;
args.push_back(Value(0.016));   // delta time
args.push_back(Value("frame"));
interp.callGlobal("_process", args);

// Recoger el valor de retorno
Value v = interp.callGlobal("obtener_puntuacion");
if (v.isNum()) std::cout << "Puntuación: " << v.asNum() << "\n";

callGlobal lanza NimbleError si la función no existe o no es invocable.

Sandbox y permisos

El intérprete expone interp.permissions, un struct SandboxPermissions. Por defecto todo está permitido, para que el CLI se comporte igual que siempre. En modo embebido puedes restringir antes de ejecutar cualquier script.

CampoControla
allowFileReadread, exists
allowFileWritewrite, append
allowFileSystemOpsdelete, listdir, mkdir, rmdir
allowFileModulesuse "archivo.nimble" y módulos de archivo
allowSystemExecsystem.run, system.exec
allowNetworkhttp.get, http.post, y todo net.* v0.10 (tcp_listen, tcp_connect, udp_socket, resolve)
allowEnvReadenv.get, env.has, env.all
allowEnvWriteenv.set
allowExit v0.8exit()
confineToRoot + sandboxRootConfina todas las rutas a una carpeta base

Ejemplo: bloquear todo lo peligroso

Interpreter interp;

interp.permissions.allowFileRead      = true;
interp.permissions.allowFileWrite     = false;
interp.permissions.allowFileSystemOps = false;
interp.permissions.allowFileModules   = true;
interp.permissions.allowSystemExec    = false;
interp.permissions.allowNetwork       = false;
interp.permissions.allowEnvRead       = true;
interp.permissions.allowEnvWrite      = false;
interp.permissions.allowExit          = false;

// Confina toda I/O a ./scripts/assets/
interp.permissions.confineToRoot = true;
interp.permissions.sandboxRoot   = "./scripts/assets";

// ... ejecutar script ...
Aviso honesto sobre el sandbox: el confinamiento de rutas es una defensa léxica (normalización). No protege contra symlinks que apunten fuera del sandbox. Si necesitas aislamiento real, considera ejecutar el intérprete en un proceso separado con seccomp, contenedor, o similar.

Límites de ejecución

Para protegerte contra bucles infinitos y recursión descontrolada:

Límite de pasos

interp.setStepLimit(1'000'000);   // máximo de "pasos" (iteraciones y similares)

Límite de tiempo

interp.setTimeLimit(2.5);   // segundos

Profundidad de recursión

interp.maxCallDepth = 200;   // por defecto 500 (importante si usas hilos con stack chico)

Cuando se excede un límite, se lanza Interpreter::ExecutionLimitExceeded. Esta excepción no es capturable por try/catch del script: si lo fuera, un script malicioso podría escapar del límite simplemente atrapándola. 

Interpreter interp;
interp.setStepLimit(100000);
interp.setTimeLimit(1.0);

try {
    interp.run(program);
} catch (Interpreter::ExecutionLimitExceeded& e) {
    std::cerr << "Script excedió el límite: " << e.message << "\n";
}

Cuándo llamar a checkLimits

Internamente se llama en bucles while/for y otros puntos calientes. Si tu host necesita control más fino (por frame), puedes llamar interp.checkLimits() manualmente entre hooks.

Módulos embebidos en el ejecutable

Si distribuyes un solo binario, puedes empotrar los módulos .nimble dentro del ejecutable en vez de leerlos del disco: 

std::unordered_map<std::string, std::string> modulos;

// La clave es la ruta resuelta por el intérprete. Por ejemplo, si el
// script hace  use "utilidades.nimble"  y scriptDir es ".",
// la clave será algo como "./utilidades.nimble" (normalizado).
modulos["./utilidades.nimble"] = R"(
func sumar(a, b)
    return a + b
end
)";

Interpreter interp;
interp.embeddedSources = &modulos;

// Ahora use "utilidades.nimble" tomará el módulo del mapa.
Cuando embeddedSources está activo, cualquier use "archivo.nimble" se busca primero en el mapa. Si no está, se lanza "Module not bundled into the executable: ...".

Trabajar con Value

La clase Value es el tipo de todos los valores del intérprete. API relevante:

Construcción

Value d(3.14);                    // number (double)
Value n(42);                      // number (int)   -- ver nota v0.9 abajo
Value b(true);                   // boolean
Value s("hola");              // string (const char*) -- ver nota v0.9 abajo
Value s2(std::string("hola"));  // string (std::string), sigue funcionando igual
Value nul;                        // null

// Lista
auto l = std::make_shared<ListObj>();
l->items.push_back(Value(1));
l->items.push_back(Value(2));
Value lista(l);

// Mapa
auto m = std::make_shared<MapObj>();
m->set("clave", Value(42));
Value mapa(m);
Cambio importante en v0.9 fix: Value(int) y Value(const char*) se añadieron en v0.9. Antes:
  • Value(42) era un error de compilación (ambiguo entre Value(double) y Value(bool)).
  • Value("texto") compilaba sin ningún error ni warning, pero el resultado era Value(true) — un booleano — porque la conversión estándar de puntero a bool gana la resolución de sobrecarga frente a la conversión definida por el usuario de const char* a std::string.

Si tienes código de embebido escrito antes de v0.9 que evitaba este problema envolviendo literales manualmente (Value(std::string("texto")) o Value((double)42)), ese código sigue funcionando exactamente igual. El riesgo está solo en código nuevo que hoy escriba Value("texto") o Value(42) esperando el comportamiento antiguo (compilar distinto o fallar); ahora ambos hacen lo obvio.

Consulta

if (v.isNum())    { double d = v.asNum(); ... }
if (v.isStr())    { const std::string& s = v.asStr(); ... }
if (v.isBool())   { bool b = v.asBool(); ... }
if (v.isList())   { auto l = v.asList(); ... }

if (v.isObj())    { auto e = v.asObj(); ... }

Recolector de ciclos en el host v0.7

Si tu host crea muchos objetos Nimble de larga vida (closures, clases), el recolector de ciclos funciona automáticamente. Pero también puedes exponerlo al script:

// En el script:
use gc
gc.collect()   # forzar recolección
stats = gc.stats()
print(stats.tracked)
Limitación conocida: el recolector no puede inspeccionar las capturas de un std::function nativo. Si una función nativa captura un Value que a su vez crea un ciclo, ese ciclo no será detectado. En la práctica, esto solo afecta a wrappers nativos creados dinámicamente y almacenados en objetos de larga vida.

Ejemplo completo: scripting de juego

// game.cpp
#define NIMBLE_NO_MAIN
#include "nimble.cpp"
#include <iostream>

int main() {
    Interpreter interp({"game"});

    // --- Sandbox: script de usuario con permisos mínimos ---
    interp.permissions.allowFileRead      = false;
    interp.permissions.allowFileWrite     = false;
    interp.permissions.allowFileSystemOps = false;
    interp.permissions.allowFileModules   = false;
    interp.permissions.allowSystemExec    = false;
    interp.permissions.allowNetwork       = false;
    interp.permissions.allowEnvRead       = false;
    interp.permissions.allowEnvWrite      = false;
    interp.permissions.allowExit          = false;

    // --- Límites ---
    interp.setStepLimit(500000);
    interp.setTimeLimit(1.0);   // 1 s por llamada a _process
    interp.maxCallDepth = 300;

    // --- API del motor expuesta al script ---
    interp.registerNative("spawn_enemigo",
        [](std::vector<Value>& a, auto&, Interpreter&) -> Value {
            std::string tipo = a.empty() ? "goblin" : a[0].asStr();
            std::cout << "[motor] spawn " << tipo << "\n";
            return Value((double)std::rand());
        });

    interp.registerNative("get_delta",
        [](std::vector<Value>&, auto&, Interpreter&) -> Value {
            return Value(0.016);
        });

    // --- Cargar script del usuario ---
    std::string src = R"(
func _ready()
    print("Script listo")
    self.tiempo = 0
end

func _process(dt)
    self.tiempo = (self.tiempo ?? 0) + dt
    if self.tiempo > 1.0
        spawn_enemigo("orco")
        self.tiempo = 0
    end
end
)";

    Lexer lex(src);
    auto toks = lex.tokenize();
    Parser parser(toks);
    auto program = parser.parseProgram();

    try {
        interp.run(program);
        interp.callGlobal("_ready");

        // Simular 3 segundos de frames
        for (int i = 0; i < 180; ++i) {
            std::vector<Value> args{ interp.callGlobal("get_delta") };
            interp.callGlobal("_process", args);
        }
    } catch (Interpreter::ExecutionLimitExceeded& e) {
        std::cerr << "Script excedió límites: " << e.message << "\n";
    } catch (NimbleError& e) {
        std::cerr << "Error en el script: " << e.what() << "\n";
    }

    return 0;
}
